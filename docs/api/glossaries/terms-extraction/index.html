Terms Extraction

Terms extraction finds the terms worth keeping consistent in a text (names, product features, defined terms, domain vocabulary) and adds them to a glossary, translated into every language of that glossary.

It works in two steps, so you can review the candidates before anything is added:

  1. Extract. POST /translation/glossaries/{id}/extract starts a background task that returns term candidates. The glossary does not change.
  2. Save. After your review, POST /translation/glossaries/{id}/terms/save translates the terms you kept into all glossary languages and adds them.

Both steps return a taskId. Follow a task with GET /translation/glossaries/tasks/{taskId}, or pass a callbackUrl to be notified when it finishes (see Callbacks). To skip the review, send autoSave: true with the extraction and it saves the new candidates itself.

Billing

Extraction is free. Saving is billed by words, for the translations of the saved terms. A term’s own language and terms that are skipped or fail to translate are not billed. Extraction still needs an active plan with quota left, and is refused with 402 otherwise.

Tip

Add the language of your text to the glossary languages before saving. Terms are translated from whatever language they are in into every glossary language, and only languages the glossary has are stored. Not sure which language the text is in? Use Detect Language.

Get Extraction Options

Section titled “Get Extraction Options”

Returns the limits for extraction and saving, the depth levels, and ready-made instruction presets.

Endpoint: GET /translation/glossaries/extract/config

Response

Section titled “Response”

Success Response (200)

Field Description
limits.maxTextLength Longest text accepted by extraction, in characters
limits.maxCustomPromptLength Longest customPrompt, in characters
limits.maxTerms Highest allowed maxTerms
limits.maxSaveTerms Most terms per save request
limits.maxTermLength, limits.maxDefinitionLength Longest term and definition accepted by save, in characters
depths, defaultDepth Accepted depth values and the one used when you send none
presets Instruction texts for common kinds of content: game-lore, software-ui, legal, medical and marketing. Send a preset’s instructions as customPrompt as it is, or adapt it to your content

Extract Terms

Section titled “Extract Terms”

Starts extracting term candidates from a text. Long texts are split into parts that are processed in parallel. The glossary does not change unless you send autoSave: true.

Endpoint: POST /translation/glossaries/{id}/extract

Path Parameters

Section titled “Path Parameters”
  • id: The glossary ID

Request Body

Section titled “Request Body”

Sent as JSON.

Field Type Required Description
text string yes Text to extract terms from, up to limits.maxTextLength characters
customPrompt string no Your instructions for what to extract, for example “Include every character, place and spell name.” They take precedence over the default selection criteria. A preset is a good starting point
depth string no How many terms to aim for. key: only the core terms a translator must keep consistent. balanced (default): every term worth keeping consistent, skipping obvious words. exhaustive: every candidate, including minor names and one-off mentions
maxTerms integer no Upper bound on the number of new candidates, 1 to limits.maxTerms. The ones that occur most often in the text are kept
includeDefinitions boolean no Generate a short definition for each term (default true). Turn it off for a term list only: it is faster and leaves room for more terms
autoSave boolean no Translate and save the new candidates without review (default false). The task then has the type extract_and_save and is billed like a save
callbackUrl string no An https URL that receives an event when the task finishes. See Callbacks

Response

Section titled “Response”

Accepted (202)

Error Responses

Status When
400 Invalid body, for example a text longer than limits.maxTextLength or a callbackUrl that is not https
402 The organization has no quota left or has unpaid invoices
404 The glossary does not exist in your organization

  • nodejs

Get Task Status

Section titled “Get Task Status”

Returns the state, progress and result of an extraction or save task. Poll every few seconds until state is succeeded or failed. Tasks are kept for 7 days.

Endpoint: GET /translation/glossaries/tasks/{taskId}

Path Parameters

Section titled “Path Parameters”
  • taskId: The task ID returned when the task was started

Response

Section titled “Response”

Success Response (200), a finished extraction:

Field Description
type extract, save, or extract_and_save for an extraction with autoSave
state pending, running, succeeded or failed
progress phase is extracting (done/total count text parts) or saving (they count terms). null before the task starts
error Why the task failed, when state is failed
result Set once the task has finished. The fields below depend on the task type

Extraction result (extract and extract_and_save)

Field Description
terms Candidates, each with term, definition, occurrences (how often it occurs in the text) and exists. New candidates come first, ranked by occurrences, then the terms the glossary already has (exists: true)
chunks Number of parts the text was split into
failedChunks Zero-based indexes of parts that could not be processed. The candidates from the other parts are still returned; run the extraction again to cover these parts
truncated true when maxTerms cut off some candidates

Save result (save and extract_and_save)

Field Description
added Number of terms translated and saved
skipped Terms not saved, each with term and reason (exists when the glossary already has it)
failed Terms that could not be translated, each with term and error. They were not saved or billed

Save Terms

Section titled “Save Terms”

Translates terms into every language of the glossary and adds them. Send the final list after your review: leave out the candidates you rejected, include terms you added yourself, and send edited terms and definitions as they are. The review happens on your side, so you can also save terms that did not come from an extraction.

Terms the glossary already has are skipped, so resending the same request is safe. If you already have translations for your terms, use Create Multiple Terms (Bulk) instead.

Endpoint: POST /translation/glossaries/{id}/terms/save

Path Parameters

Section titled “Path Parameters”
  • id: The glossary ID

Request Body

Section titled “Request Body”

Sent as JSON.

Field Type Required Description
terms array of objects yes Terms to save, up to limits.maxSaveTerms
terms[].term string yes The term, up to limits.maxTermLength characters
terms[].definition string no A short definition, up to limits.maxDefinitionLength characters. It is translated along with the term
extractionTaskId string no The extraction task the terms came from, if any
callbackUrl string no An https URL that receives an event when the task finishes. See Callbacks

Response

Section titled “Response”

Accepted (202)

Follow the task with Get Task Status. Its result has added, skipped and failed.

Error Responses

Status When
400 Invalid body, for example too many terms
402 The organization has no quota left or has unpaid invoices
404 The glossary does not exist in your organization
409 The glossary is being updated, for example by another save task. Wait for it to finish and retry

Callbacks

Section titled “Callbacks”

Instead of polling, pass a callbackUrl when you start a task. When the task finishes, the platform sends a POST request with a JSON event to that URL:

The event carries no result: fetch it with Get Task Status. state is succeeded or failed.

  • The URL must use https, must not contain credentials, and its host must resolve to a public address. Otherwise the request that starts the task fails with 400.
  • Answer with any 2xx status to acknowledge the event. Otherwise delivery is retried up to 4 times: after 1 minute, 5 minutes, 30 minutes and 2 hours.
  • A retry has the same eventId, so use it to drop duplicates.
